# Harness Slides 0.14.1

Closes the gaps Training Studio found while integrating the design-bound
composition review: a Google render for `review`, every review packet in one
call, refusals a caller can act on, sources taken from the slide, and a way to
put a deck with findings to the person.

## Review

- **Rendering through Google.** `review --compiled` and `review --file` take
  `--renderer google [--file-id ID]`, the Drive route `compose preview
  --renderer google` uses. Poppler is checked before anything is uploaded. The
  exact bytes of `REVIEW/deck.pptx` that the review hashes are imported as
  `Preview: <title>`, or replace the `--file-id` file, exported as a PDF and cut
  into pictures. `builtArtifactDigest` is the hash of the uploaded bytes and
  `artifactDigest` the hash of Google's pictures; the reviewed deck is still
  `REVIEW/deck.pptx`. The record keeps `remote`, and the result returns
  `fileId`, `url` and a `next`. An unchanged build uploads nothing. Drive
  failures are `provider-failed` (`google`) and name the file to reuse. `local`
  (LibreOffice) stays the default.
- **Every packet in one call.** `review --output REVIEW --packets` returns, for
  every slide in deck order, its number, rendered and plan IDs, picture path and
  hash, pixel mark, the packet `--slide` returns and its findings, with the
  assessment binding, `designReview` and the readiness flags. `review.json`
  stays an internal record.
- **Sources from the slide.** A `review --assessment` check that leaves out
  `sources` takes its slide's, and they are stored filled in. Sources that are
  given must be a non-empty list drawn from the slide's; otherwise the check is
  refused as `input-invalid`, naming the slide, the criterion and the stray
  source.
- **Refusals.** "Prepare native review first" (now naming the folder) and
  "Prepare and mark are separate operations" are `input-invalid`, each with a
  `next` naming the step. A missing LibreOffice names `--renderer google` in
  `next`.

## Design approval

- **Presenting with findings.** `design present --accept-findings` presents a
  review whose pixels are all marked `reviewed` and whose assessment is complete
  but leaves findings unresolved. The findings, keyed by plan slide ID, are part
  of the render binding. The rendered question lists them and offers "Approve
  these slides with the findings listed"; `design status` returns
  `renderedFindings`. Only `design respond` with the person's words approves,
  recorded with `acceptedFindings`. An earlier waiver of the rendered checkpoint
  does not cover findings, `approve-remaining` is refused when a slide outside
  the question has findings, and a changed assessment makes the presentation
  stale.

## Runtime

- `version` adds five capabilities: `design-present-findings`,
  `review-google-renderer`, `review-input-refusals`, `review-packets` and
  `review-sources-from-slide`.
- Live guidance describes `--packets`, `--renderer google`, sources from the
  slide and `design present --accept-findings`.

## Changed behavior

- Current public guidance requires runtime 0.14.1. A 0.14.0 runtime falls back
  to the last guidance it supports, `d12f6d11b45b9000746ce5a79084e614386a0c2f`,
  and says an update exists.
- The two review refusals above now have the code `input-invalid`. Defaults,
  other refusal codes and messages, a clean deck's render binding, the session
  shape and status strings are unchanged.

## Verification

On the release tree, on an Intel Mac (macOS 15.7.9, Node 25.9.0, Python 3.9.6
with Pillow), not in the Tart gate:

- `npm ci` from the lockfile.
- `npm test`: 284 tests, 281 pass, 3 skipped, 0 fail. The three skipped are
  the real-browser, real-rendering and exact-font checks, which need Chromium,
  LibreOffice and Poppler.
- `npm run context:check` passed after `context:update`.
- The installer into disposable home and shared paths; the installed runtime
  reports 0.14.1 and lists its seventeen capabilities.
- `workspace init` and `workspace build` of `examples/scene.json` from that
  installed runtime. The example was not reviewed: `review` renders with
  LibreOffice or through Google Drive.

## Known limitations

- **No render or browser checks.** The macOS Tart gate was not run: it cannot
  run on the Intel Mac used for this release, and LibreOffice, Poppler and
  Chromium were not installed there. The suite's real-browser and
  real-rendering checks were skipped, no deck was rendered, and no example was
  reviewed.
- **Google review render not checked live.** `review --renderer google` was
  exercised only by its tests, with Drive and Poppler replaced by stand-ins. It
  has not rendered a deck through a real Drive account.
- **Google import not checked.** Neither the native charts nor the native icons
  procedure under `docs/verification/` has been run.
- **Gemini API provider unverified live** (#41).
- **Lettered icon render comparison not done** (#43).
- No deck was opened in PowerPoint or Google Slides.
