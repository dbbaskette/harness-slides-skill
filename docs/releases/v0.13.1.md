# Harness Slides 0.13.1

One fix: rendering from a template that binds the relationships prefix only
where it is used.

## Fixed

- **`compose render` and `compose preview` no longer fail with `unbound
  prefix`** when a brand's native template binds `r` on each element of
  `ppt/presentation.xml` that carries `r:id`, and not on the root. Such a file
  is well formed and opens in PowerPoint and Google Slides. The emitter now
  binds a prefix on a part's root before it leaves a use of that prefix there.
  A root that already binds the prefix is left as it was, so decks from other
  templates do not change, and masters, layouts and themes are still copied
  byte for byte.
- **Entries are never dropped without a word.** The slide list, the
  presentation relationships and the content types each had entries added
  before a literal tag. A part written with other prefixes has no such tag, so
  the entries were lost silently: with prefixed content types the render
  succeeded and the deck did not declare its slides. Such a template is now
  refused, naming the part.
- **A failed render leaves nothing behind.** The failed render used to leave a
  file under the output name that could not be opened and that blocked the
  retry. The native emitter now writes the deck and reads it back in its
  private folder, and copies it to the output only once it reads back. An
  existing file is still refused and left alone.

## Changed behavior

- A template whose slide list, presentation relationships or content types are
  written with other prefixes is refused at render. Before, it rendered a deck
  that was missing those entries.

Current public guidance still requires runtime 0.13.0. Guidance is unchanged,
so `guidance/manifest.json` and `guidance/compatibility.json` are as they were
in 0.13.0.

## Verification

Three new tests, each failing on the scripts as they were, with a small
template the test builds itself. The release tree passed the clean macOS Tart
gate in a disposable clone before it was merged: a fresh dependency install and
audit, the whole suite with the real-browser and real-rendering checks enabled,
the context check, the installer into disposable paths, the version reported by
that installed runtime, and an example build and review. The release ZIP was
made from the merge commit, its files compared with the tagged tree, and its
installer run into disposable paths.

Against a real template that shows the failure, 0.13.0 exits 1 and leaves the
file; this release renders the deck and every XML and relationship part of it
parses. Only `presentation.xml` differs from what 0.13.0 would write, by the
one root declaration.

Not verified: the deck was not opened in PowerPoint or Google Slides, and no
preview was made through Drive. Live-deck acceptance from 0.13.0 is reused.
