# Meaningful icon opportunities

Use this pass when creating/redesigning slides or when the user asks to improve
or add icons to an existing deck. For brand-only work, retain content imagery;
replace an inspected nonbrand symbol only when the scope permits it. Do not turn
a typography-only edit into an icon project.

Inspect the rendered slides first. Consider icons for distinct capabilities,
process stages, roles, security boundaries, or responsibilities when recognizable
symbols will help the audience scan or distinguish them. An existing suitable
icon may simply be retained. Dense tables, exact metrics, code, and required
screenshots often work better without additional icons. No icon quota or grid.

For each selected opportunity, record the slide/object, existing concept or label,
why the icon helps, keep/replace/add, and the approved catalog ID and treatment.
A short list beside the existing change plan is enough; do not require a new
approval round when the user has already authorized these additions.

Search the selected brand's installed catalog by meaning, preview the actual
candidate, then choose it. Never infer suitability from a filename or search
rank alone. Do not invent a brand glyph, use emoji as icons, or fetch assets from
an unapproved source. If no approved equivalent exists, keep the label or original
business image and report the exception. Do not substitute a generic security
icon for a specific certification or imply a product capability not in the copy.

Use the same glyph for the same concept across the deck. Keep one icon treatment
and color per slide, consistent scale, and adequate label separation. Preserve
numbers that carry sequence, labels, links, arrows, QR codes, and product marks.
Icons supplement the meaning; they do not replace required wording or evidence.
Keep placement inside the existing composition for a polish task. New diagrams
or structural changes require the corresponding redesign scope.

Use native editable geometry when supported by the approved library and chosen
authoring method. Harness Slides' native icon and asset capabilities are preferred
for compatible catalogs; a brand add-on may supply its own editable geometry.
Preserve aspect ratio and attach a concise descriptive name. A PNG preview is
not proof of native editability. Do not flatten the slide to add an icon.

Render the affected slides and inspect glyph clarity, contrast, spacing, reading
order, and repeated concepts. Verify existing text/data/notes/links are retained
and review the destination-native rendering after conversion. Record any icon
that remains rasterized or whose provenance could not be verified.

## Scenario checks

- Four labeled process stages: choose distinct approved concepts, keep the step
  numbers and wording, and use consistent treatment without changing the flow.
- A dense numeric comparison: retain readable table rows; add no icons merely to
  fill space or decorate column headers.
- A product logo beside a capability: preserve the logo; it is not a candidate
  for a generic catalog replacement.
- No approved symbol for an unfamiliar concept: retain the explicit text, rather
  than inventing a metaphor or a new brand icon.
