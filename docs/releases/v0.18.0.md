# Harness Slides 0.18.0

Polishing an existing deck now has an alignment audit and a change summary.

`pptx align --file deck.pptx` reports peers that are almost aligned, almost the same
size or unevenly spaced. With `--output` it settles them: rows share a top edge,
columns a left edge, same-size plain panels one size, near-equal gaps become equal.
A shape that moves carries the shapes drawn inside it. Only the offset and size tags
of moved shapes are rewritten; wording, objects and order must match or no file is
written. Icon parts, different artwork and centred or bottom-anchored loose text are
left alone, and what geometry cannot decide (mixed text anchors in a row of cards,
unequal card widths, a content block short of the title's margin) is listed for the
reviewer.

`pptx changes --file before.pptx --after after.pptx [--output summary.md]` writes a
slide-by-slide summary of what moved, was resized, restyled, reworded, added or
removed, for the person to check against the deck. Charts, tables and connectors
are not compared.

Guidance for scoped edits asks for both on a polish pass, falls back to a
hand-written summary on older runtimes, and records that a Google deck reached only
through Drive can be replaced in place with an upload update to the same file.
Capabilities `pptx-align` and `pptx-changes` are added. The minimum runtime for
current guidance stays 0.17.0.

The rules were tuned on one 45-slide branded Google export; treat the audit as a
floor and still render and inspect every changed slide.
