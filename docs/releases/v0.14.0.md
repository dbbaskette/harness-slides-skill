# Harness Slides 0.14.0

Visual teaching for decks built against an approved design: richer design
proposals, a whole-plan question, refusals a caller can read, section builds,
an asset manifest, a review against the design, and native charts in
compositions. Built for Training Studio's visual teaching plan.

## Design approval

- **Proposal schema 2.** Each slide may carry `objectives`, `copy` (from which
  `visibleText` is rendered), `qualifications` the copy must keep, presenter
  `notes` outside the approval, and `asset.candidates`. Schema 1 is still
  accepted and stored as before. A visual that needs an asset that is not
  selected is refused as `asset-unresolved`, with a native-diagram fallback that
  needs approval like any change.
- **Whole-plan question.** `design propose --mode batch` asks about every pending
  slide at once; one `approve` of `Approve the whole plan` approves them all.
- **Refusals as data.** `--json` on `design`, `assets` and `images` actions,
  `compose compile`, `compose preview` and `review` prints
  `{status:"blocked",problems:[{code,slide,asset,provider,detail,recoverable,next}]}`
  on stdout and exits 1. Without it, stderr reads as before.
- **Section-scoped gate.** `compose compile` and `compose preview` take
  `--design-project DIR --section`. A section is a contiguous run of approved
  slides; a refusal names the slide that is missing, extra, out of order,
  retitled or given a changed `intent`. `compose compile --design-project` now
  checks the design without `--output` too, and `compose preview
  --design-project` rechecks it before rendering.
- **Canonical digests.** Intents, slide approvals and plan revisions ignore key
  order. A proposal resent with only its key order changed is unchanged and keeps
  its approvals.
- **Relative paths.** The design session, review records, workspace manifests and
  compile reports keep paths inside the project relative, so a project can move
  or be committed. Older records still read and are rewritten on their next
  write.

## Assets and icons

- **Asset manifest.** `PROJECT/.harness-slides/assets.json`, written by `assets
  add-supplied`, `assets icon`, `images generate` and `images download`, and
  checked by `assets status|check`. Compositions place a recorded image as
  `{type:image,asset:ID}` or `picture:{asset:ID}`; the build copies it and
  `compose-report.json` lists it in `inputs.assets`.
- **Exact icons.** An icon candidate can name a brand library ID with
  `refType: "library-id"`, checked by `design propose --brand` and `assets check
  --brand --design-project`. A composition places a recorded icon as
  `{type:icon,asset:ID}`. `assets status|check --design-project` now read the
  candidates of every slide in the stored plan, pending or approved.
- **Lettered icons.** The icon indexer keeps lettering that sits on an icon's
  disc (it used to drop it, leaving only the disc), and text inside a copied icon
  now scales with the icon.
- **Native icon copy.** Copying an icon no longer fails with "Mapped icon shapes
  are missing" when a table on the library slide shares a shape ID with the
  icon's disc.

## Review and charts

- **Design-bound composition review.** `review --compiled COMPILED --output
  REVIEW --design-project DIR` renders `REVIEW/deck.pptx` and reviews it against
  the approved design. `designReview` sorts findings into asset failures, design
  deviations, visual teaching, fit defects and approved direct text. A mechanism
  drawn as boxes of prose gets a `prose-cards` prompt and a required
  `teaching-treatment` criterion.
- **Native charts.** A composition `chart` node (`bar`, `line` or `pie`) is
  written by the native template emitter as an editable chart with its own
  embedded workbook, in the brand's chart colors.

## Runtime

- **`version` reports `capabilities`**, a sorted list of feature names a caller
  can test for instead of comparing versions.
- **Guidance cache hardening.** Each `start` and `pin` deletes the project's
  guidance repository and fetches into a fresh one, so a planted repository
  cannot choose the guidance. The fallback and `pin` paths now fetch `main`'s
  full history each time.

## Changed behavior

- Current public guidance requires runtime 0.14.0. A 0.13.x runtime falls back
  to the last guidance it supports, `fb1e30e5fc6f72f0dca2208c31ed88a264922775`,
  and says an update exists.
- `assets check --design-project` refuses an approved design with unrecorded
  candidates; before, it saw none once the design was approved.
- A brand's checked-in icon index keeps a lettered icon's disc alone until its
  maintainer regenerates it with this runtime.

## Verification

On the release tree, on an Intel Mac (macOS 15.7.9, Node 25.9.0, Python 3.9.6
with Pillow), not in the Tart gate:

- `npm ci` from the lockfile.
- `npm test`: 277 tests, 274 pass, 3 skipped, 0 fail. The three skipped are
  the real-browser, real-rendering and exact-font checks, which need Chromium,
  LibreOffice and Poppler.
- `npm run context:check` passed after `context:update`.
- The installer into disposable home and shared paths; the installed runtime
  reports 0.14.0 and lists its twelve capabilities.
- `workspace init` and `workspace build` of `examples/scene.json` from that
  installed runtime. The example was not reviewed: `review` renders with
  LibreOffice.

The ZIP was made with `git archive` from the tagged merge commit, its files
compared with the tagged tree, and its installer run into disposable paths.

## Known limitations

- **No render or browser checks.** The macOS Tart gate was not run: it cannot
  run on the Intel Mac used for this release, and LibreOffice, Poppler and
  Chromium were not installed there. The suite's real-browser and
  real-rendering checks were skipped, no deck was rendered, and no example was
  reviewed. `review --compiled` was exercised only by its tests.
- **Google import not checked.** Neither the native charts nor the native icons
  procedure under `docs/verification/` has been run, so what Google Slides makes
  of a composition chart is unknown. The compositions guidance says so and asks
  for a look at each chart in the Google preview.
- **Gemini API provider unverified live** (#41): it has never made a live
  request.
- **Lettered icon render comparison not done** (#43): lettered icons from a real
  brand were not rendered and compared with their previews.
- No deck was opened in PowerPoint or Google Slides.
