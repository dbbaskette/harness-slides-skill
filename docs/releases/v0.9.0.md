# Harness Slides 0.9.0

New decks and substantial redesigns now propose each slide's content, composition
and visual assets before construction, then wait for actual user responses through
the available Claude/Codex question interface or chat. Guided, batch and explicit
autonomous decisions retain feedback and invalidate affected approvals on revision.
The finished rendered deck has its own user review checkpoint.

Native-template and compiled PPTX reviews now bind source/object decisions,
expected text and assets to the actual rendered revision. Pixel coverage, structured
creative critique and user acceptance remain distinct. Missing selected assets,
incomplete export text and boilerplate creative judgments stay unresolved.

Design guidance asks for content-led construction, a strongest feasible alternative,
visual hierarchy and clearly attached labels. Choose approximately 3–4 content
colors from the selected brand; there is no fixed preferred palette or artwork quota.

Current public guidance requires runtime 0.9.0. Saved tasks retain their older
immutable runtime and guidance; release installation does not remove saved versions
or change authenticated image sessions. The version command and skill start report
the actual runtime in use.

Verification uses the existing combined Brand Tart gate for full Slides tests,
browser/PPTX rendering, optional image-worker fixtures, isolated installers and
version reporting. Hand-authored demo renders support design review; fresh
Claude/Codex prompt-generation and signed-in image-generation acceptance are not
claimed by these release tests. Existing Google decks are not changed by updating.
