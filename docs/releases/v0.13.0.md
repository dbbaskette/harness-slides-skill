# Harness Slides 0.13.0

More to draw with, a look chosen from real slides, an independent review
before delivery, and a runtime that no longer stops working when guidance moves
ahead of it.

## Drawing

- **Box styles:** `outline` and `bar` beside `solid`, so supporting cards stop
  competing with the point of the slide.
- **`metric`, `badge`, `rule`:** a number with its label, a small numbered
  disc, and a thin divider.
- **Edges:** `route` is `elbow` or `curve`. An edge now runs the way the layout
  does, across in a row and down in a column, so a parent above its children
  leads off downward. Edges stay attached to hexagons, chevrons, cans and icon
  discs as well as rectangles, ellipses and diamonds.
- **`ring`:** three to eight nodes around a circle with an optional hub. A
  bent edge between two of them turns once around the outside, which draws a
  cycle.
- **`table`:** a native table in the brand's table style, with rows as tall as
  their tallest cell.
- **Pictures:** a cover or section layout with a picture slot takes
  `picture:{src,alt}`, cropped to fill the slot. Words over an image are
  refused unless a filled box sits behind them.
- **Icon screens:** `preview` reports an icon repeated across a slide, an icon
  with no words beside it, and one icon given two meanings. An icon whose
  library entry is only a disc is refused at compile.

## Process

- **Gallery and a shorter design page:** one finished example for each
  relation, and the design page cut to a five-step procedure with a short list
  of things not to do.
- **Choose the look from real slides:** after the draft is approved, one slide
  is built two or three ways and shown side by side with `compose sheet`. The
  user's pick becomes the deck's direction. The outline's `approval` carries
  what they said into the build's brief.
- **Independent review:** a whole-deck preview writes `contact-sheet.png` and
  `critic.json`. `compose critique` records a reviewer's graded findings; a
  critical finding blocks delivery.

## Images

- **Gemini API provider:** `images generate` uses the Gemini API with
  `GEMINI_API_KEY` or `GOOGLE_API_KEY`. One image per call, a receipt per ID,
  and no resend of a request Google may have received. The older cookie route
  stays behind `--provider gemini-web`.
- **Art style:** `art-style.txt` in the project is sent before every brief and
  its hash is recorded with each image.
- **`--api generate-content`:** the earlier request shape, one flag away.

## Guidance and runtime

- **Fallback:** when current guidance needs a newer runtime, a new task uses
  the last guidance the installed runtime supports and says so, instead of
  stopping. `guidance/compatibility.json` lists those commits.

## Changed behavior

- A straight edge between nodes in different rows of a column now leaves the
  bottom of one and meets the top of the other; before, it could leave from a
  side.
- Text placed directly over an image in a `free` container is now refused.
- `images generate` defaults to the Gemini API and needs a key; the cookie
  route must be asked for.

Current public guidance requires runtime 0.13.0. Runtimes up to 0.12.0 predate
the fallback and are refused until updated.

## Verification

Unit tests: 213 pass, 3 skipped. Edges, rings, the table, picture slots and a panel
over a photo were rendered through Google Slides on a brand template and
inspected by eye; every connector kept its attachment after a Drive import and
export. A fresh agent ran the look step from an approved draft and its report
drove a round of fixes, and a fresh reviewer found planted defects that the
automatic screens missed.

Not verified: the Gemini API provider has never made a live request, so the
model name, request shape, cost and image format are from Google's
documentation only. Native charts are still not available in compositions.
The combined Tart gate was not run and no output was opened in PowerPoint.
